### 🧠 1. Entendiendo la lógica del Backend

El backend es un servidor Node.js que funciona como una API REST. Aquí te resumo las reglas de negocio que debes tener en cuenta para diseñar la interfaz:

1. **Dos tipos de tickets:** Tenemos dos diseños (`ticket1` y `ticket2`). Al generar un ticket, debes indicar qué tipo es.
2. **Seriales únicos:** Los tickets van del `0000` al `9999`. Si intentas generar uno y la base de datos está llena, el backend te devolverá un error de "Capacidad máxima alcanzada".
3. **QR de un solo uso:** Esta es la regla de oro. Un ticket **solo se puede usar una vez**. Si se escanea de nuevo, el backend rechazará el acceso. El QR contiene un JWT (un token largo de texto) que es lo que debemos enviar al backend para validarlo.
4. **Panel de Administrador:** Algunas rutas (como ver todos los tickets o generar en lote) están protegidas. Necesitarás hacer un login de administrador para obtener un token JWT y enviarlo en los headers.

### 🌐 2. Los Endpoints que vas a consumir

Aquí tienes la "receta" de las rutas. Todas devuelven respuestas en formato JSON.

#### A. Generar un ticket (Público)
* **Ruta:** `POST http://localhost:3000/api/tickets/generate`
* **Body (JSON):** `{ "tipo": "ticket1" }` (o `ticket2`).
* **Respuesta:** Te devuelve el `serial`, el `uuid`, y lo más importante: `imagenBase64`. Es la imagen final del ticket en texto base64. Solo tienes que ponerlo en un `<img src="data:image/png;base64,..." />` en tu HTML.

#### B. Validar un ticket (El lector QR)
* **Ruta:** `POST http://localhost:3000/api/tickets/validate`
* **Body (JSON):** `{ "token": "EL_TOKEN_LEIDO_DEL_QR" }`
* **Respuesta:** 
  * Si todo bien: `{ "valido": true, "serial": "0045", "mensaje": "Acceso permitido" }`
  * Si ya se usó: `{ "valido": false, "motivo": "Ticket ya utilizado" }`
  * Si es falso: `{ "valido": false, "motivo": "Ticket inválido" }`

#### C. Login Admin
* **Ruta:** `POST http://localhost:3000/api/admin/login`
* **Body:** `{ "username": "admin", "password": "cinema115admin" }`
* **Respuesta:** `{ "token": "..." }` Guarda este token en una variable de sesión (`$_SESSION`) en PHP.

#### D. Descargar PDF (Admin)
* **Ruta:** `GET http://localhost:3000/api/tickets/download-pdf?desde=0000&hasta=0099&tipo=ticket1`
* **Headers:** `Authorization: Bearer <token_admin>`
* **Respuesta:** No es JSON, es un archivo PDF binario. Debes forzar su descarga en el navegador.

### 📸 3. El Reto Principal: Integrar la Cámara para leer QR

Para la página de validación, no puedes usar PHP para leer la cámara. PHP corre en el servidor. La cámara se controla desde el navegador del cliente (HTML/JavaScript). 

Aquí te explico cómo montarlo:

**Paso 1: La librería mágica**
No vas a programar un lector de QR desde cero. Vamos a usar una librería de JavaScript llamada **Html5-qrcode**. Es muy fácil de usar.
Inclúyela en tu archivo PHP de validación así:
```html
<script src="https://unpkg.com/html5-qrcode" type="text/javascript"></script>
```

**Paso 2: El HTML**
Necesitas un div donde se verá la cámara y un div para mostrar el resultado (verde para válido, rojo para inválido).
```html
<div id="reader" style="width: 300px;"></div>
<div id="result" style="font-size: 24px; font-weight: bold; margin-top: 20px;"></div>
```

**Paso 3: El JavaScript (El corazón de la validación)**
Este código JS va a pedir permiso para encender la cámara, estará buscando un QR constantemente. Cuando lo lea, detendrá la cámara y usará `fetch` (AJAX) para enviar el token a tu backend Node.js.

```html
<script>
    const html5QrCode = new Html5Qrcode("reader");
    const resultDiv = document.getElementById('result');

    function onScanSuccess(decodedText, decodedResult) {
        // 1. Detenemos la cámara inmediatamente después de leer
        html5QrCode.stop().then(() => {
            
            // 2. Mostramos un mensaje de "Validando..."
            resultDiv.style.color = "blue";
            resultDiv.innerText = "Validando ticket...";

            // 3. Hacemos la petición a nuestro backend Node.js
            fetch('http://localhost:3000/api/tickets/validate', {
                method: 'POST',
                headers: { 'Content-Type': 'application/json' },
                body: JSON.stringify({ token: decodedText })
            })
            .then(response => response.json())
            .then(data => {
                // 4. Mostramos el resultado
                if(data.valido) {
                    resultDiv.style.color = "green";
                    resultDiv.innerText = "✅ ACCESO PERMITIDO - Serial: " + data.serial;
                } else {
                    resultDiv.style.color = "red";
                    resultDiv.innerText = "❌ ACCESO DENEGADO - " + data.motivo;
                }

                // 5. Botón para volver a escanear
                const btn = document.createElement('button');
                btn.innerText = "Escanear otro ticket";
                btn.onclick = () => startScanner();
                document.body.appendChild(btn);
            })
            .catch(err => {
                resultDiv.style.color = "red";
                resultDiv.innerText = "Error de conexión con el servidor.";
            });
        }).catch(err => {
            console.error("Error al detener cámara", err);
        });
    }

    function startScanner() {
        resultDiv.innerText = "";
        // Iniciamos la cámara (pide permiso al usuario)
        html5QrCode.start(
            { facingMode: "environment" }, // Usa la cámara trasera
            { fps: 10, qrbox: { width: 250, height: 250 } },
            onScanSuccess,
            (errorMessage) => { /* Ignora errores de lectura intermedios */ }
        ).catch(err => {
            resultDiv.style.color = "red";
            resultDiv.innerText = "No se pudo acceder a la cámara. Revisa permisos del navegador.";
        });
    }

    // Arrancamos al cargar la página
    startScanner();
</script>
```

### 💡 4. Consejos de un Backend Dev para ti (Junior)

1. **CORS y Mixto de Contenido:** Nuestro Node corre en `http://localhost:3000`. Si tu PHP corre en `http://localhost:80` (o un puerto tipo 8000), asegúrate de que estés llamando a la API con `http://` y no `https://`, o el navegador bloqueará las peticiones por "Contenido Mixto". Ya configuré el CORS en el backend para que acepte cualquier origen (`*`), así que por ese lado estás libre.
2. **CURL desde PHP:** Para las peticiones del panel de administrador (como el login o descargar el PDF), usa `cURL` en PHP. Acuérdate de setear el header `Authorization: Bearer $token` cuando llames a rutas protegidas.
3. **El PDF es un Stream:** Cuando hagas el `cURL` en PHP para pedir el PDF a Node.js, no te vendrá un JSON. Te vendrán los bytes del archivo. Tienes que hacer un `echo` directo de la respuesta de cURL, pero antes dile al navegador que es un PDF usando `header('Content-Type: application/pdf');` y `header('Content-Disposition: attachment; filename="tickets.pdf"');`.
4. **Manejo de errores de cámara:** Muchos usuarios bloquean la cámara por defecto. Pon un mensaje bonito en HTML indicando "Por favor, permite el acceso a la cámara para validar tickets".

¡Tienes todo lo necesario! Si te trabas con alguna respuesta del API o necesitas que te ajuste algún formato de respuesta, me avisas y lo modifico en el backend. ¡Mucho éxito con el frontend!
